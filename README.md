# nwp_chart_web — 数値モデル天気図ビューア（ECMWF / GFS / AIFS / GSM。公開サーバー対応）

詳しくは [nwp-chart-web.md](nwp-chart-web.md) を参照。公開サーバーの方式・手順は [PUBLISH.md](PUBLISH.md)、設計・調査結果は [DESIGN.md](DESIGN.md)。

ECMWF（IFS）・ECMWF AIFS（AI予報モデル）・NOAA GFS（いずれも 0.25°）、およびローカル専用で気象庁GSM から、気象庁ビューア風の天気図PNGを作り、ブラウザで閲覧する。
[gsm_chart_web](https://github.com/masauehr/gsm_chart_web)（GSM版・旧版）と同じ機能を、複数モデルで・公開サーバーに置ける形で作ったものです。

> **関連リポジトリ**: [gsm_chart_web](https://github.com/masauehr/gsm_chart_web) は GSM（気象庁）だけを扱う**旧版（ローカル専用・調査用）**です。こちら（nwp_chart_web）が**後継**で、GSM もローカル専用モデルとして含み、ECMWF・GFS・AIFS と比較できます。GSM だけを単独で動かしたい場合は旧版も使えます（ポートが違うので同時に起動できます）。

## モデルを比較する

ECMWF（IFS）・AIFS・GFS（ローカルでは GSM も）の**同じ図を並べて**比べられます。方法は2通りです。公開サイトでもローカルでも同じ操作です。

### 方法1: 通常版の「2モデル比較」（2つのモデルを左右に並べる）
1つの図を大きく、2モデルで左右に見比べたいときに使います。

1. 通常版を開く（公開サイト: <https://masauehr.github.io/nwp_chart_web/>、ローカル: <http://127.0.0.1:8790/>）。
2. ヘッダーの **「2モデル比較」にチェック**を入れる（またはキーボードの **C**）。
3. **「左のモデル」**と**「右のモデル」**を選ぶ。左右を入れ替えるには「⇄ 入替」（予報有効時刻は保たれる）。
4. 地域ボタン・図種ボタンを選ぶと、**同じ図種・地域・予報有効時刻**の図が左右に並ぶ。
5. ←→ キー・スライダー・再生で時刻を動かすと、**左右が同時に動く**。
6. 元の1枚表示に戻すには、チェックを外す（または C）。

- 画面が狭いときは、左右ではなく上下に並びます。
- 各画像の上の見出しに「モデル名 ｜ 初期値 ＋予報時間」が出ます。
- URL に `cmp=1&model2=…` が入るので、比較画面をそのまま共有・再現できます。

### 方法2: 画用紙版の「モデル違い」（複数の図を並べて、モデルだけ変える）
いくつもの図を画面に並べたまま、あるものだけ別のモデルでも見たいときに使います。

1. 画用紙版を開く（公開サイト: <https://masauehr.github.io/nwp_chart_web/board/>、ローカル: <http://127.0.0.1:8790/board/>）。
2. **比較したい図（画像）をクリックして選択**する（選択した図は青い枠で強調されます）。
3. 上部メニュー2段目の **「モデル違い」ボタンを押す**。
4. 選択した図が、**他のモデルでも同じ範囲で**追加され、画面に並ぶ（見出しに `GFS`・`AIFS` などのモデル名が付く）。
5. ↑↓ キーで予報時間を動かすと、**全ての図が同じ予報有効時刻のまま**進む。

- **先に図を選択しないと「先に図を選択（クリック）してください」と表示され、何も追加されません。**
- 図ごとにモデルを変えたいときは、各図の見出しにある「モデル」欄でも選べます（既定は「モデル:全体」）。上部の「モデル(全体)」を変えると、全体のモデルが変わります。
- 図は重ねたり大きさを変えたりできます（操作は画面右上の「使い方」）。

### 初期値が違うモデルを比較するとき（共通のしくみ）
ECMWF・GFS・AIFS などは、**最新の初期値がモデルごとに違う**ことがあります（例: ECMWF は 18UTC、GFS は 00UTC）。そのため、初期値が違うモデルは **予報有効時刻（実際の時刻）が同じ図**を自動で探して表示します。

- 見出しに `GFS [11/04 00Z +0h]`（画用紙版）や「別の初期値・予報時刻を合わせて表示」（通常版）と出ます。
- 相手のモデルにその時刻の画像が無い（初期値より前の時刻など）ときは、「画像なし」と出ます。**←→（通常版）・↑（画用紙版）で時刻を進める**と出てきます。

## ローカルでの起動方法

### 前提
- Python は conda 環境 `met_env_310`（pygrib・cartopy・metpy・scipy・requests・pillow が入っている環境）を使います。
- **`python3` と打つと別の環境（`~/projects/.venv`）になることがあり、その場合は `ModuleNotFoundError` になります。** 下の例のように `/opt/anaconda3/envs/met_env_310/bin/python` を直接指定するのが確実です（`conda activate met_env_310` した後の `python` でも同じです）。

### 手順（初回）
```bash
cd ~/projects/nwp_chart_web

# 1) 天気図を作る（初回だけ必要）。ECMWF・GFS・AIFS・GSM の最新の揃った初期値を取得・作図（4モデルを並行）
/opt/anaconda3/envs/met_env_310/bin/python update_latest.py

# 2) サーバーを起動する（このターミナルは起動したままにする。止めるときは Ctrl+C）
/opt/anaconda3/envs/met_env_310/bin/python server.py

# 3) ブラウザで開く
#    通常版   : http://127.0.0.1:8790/
#    画用紙版（並べて比較）: http://127.0.0.1:8790/board/
```

- 1) は FT0〜72h で、モデルごとに数十分かかります（ECMWF/AIFS は約20MB、GFS は約38MB、GSM はファイル全体のため約600MB を取得）。まず試すだけなら FT を絞れます: `python update_latest.py --max-ft 12`
- 特定のモデルだけ作る場合: `python update_latest.py --models gfs aifs`
- **GSM を含めて比較したい場合**: GSM は気象庁データ（京大RISH配信）で**ローカル専用**です（公開サイトには載りません）。`update_latest.py` に含まれます。旧版 [gsm_chart_web](https://github.com/masauehr/gsm_chart_web) で取得済みのデータがあれば、再取得せずに使えます:
  ```bash
  /opt/anaconda3/envs/met_env_310/bin/python make_charts.py gsm 2026110312 --data-dir ../gsm_chart_web/data/gsm
  ```
  （日付は取得済みの初期値 YYYYMMDDHH に変える。FT3h 毎の日本域 0.125° も作られる）

### GSM の過去の初期値を手動で取得する（2026-11-10〜・ローカルのみ）
自動取得は最新だけで、3日より古い分は自動で消えます。過去の事例を見たいときは、**画面ヘッダーの「過去分取得」ボタン**から、京大RISHのアーカイブにある過去の初期値を取得して作図できます（`past_gsm.py` と、サーバーの `/api/past/*`。ローカルサーバーのときだけボタンが出ます）。
- **取得**: 日付（UTC）・時刻（00/06/12/18）・予報時間（24/48/72時間）を選んで「取得して作図」。**72時間で約0.6GB・約5分、24時間で約0.23GB・約2分**。進捗は画面に出る。
- **自動削除されない**: 手動で取得した初期値には目印（`output/gsm/<初期値>/.keep`）が付き、自動取得の `--keep-days` や `--keep` の削除から除外されます。一覧の「手動」欄に○が出ます。
- **削除**: 一覧の「GRIB2削除」（GRIB2だけ。画像と目印は残る）と「すべて削除」（画像・目印も）。**2回押す**と実行（1回目は「本当に削除」に変わり、4秒以内にもう一度）。取得・更新の実行中は削除できません。
- コマンドでも同じ: `python past_gsm.py fetch 2026101012 [--max-ft 24|48|72]` / `list` / `delete 2026101012 [--png]`。
- 初期値が RISH に無い（アーカイブに無い・未公開）ときは、エラーを出して何も取得しません。

### JRA-55（再解析）を表示する（2026-11-10〜・ローカルのみ）
気象庁の再解析 **JRA-55**（1.25°・6時間毎・1958〜2023年）を、画面の「**過去分取得**」ボタン（モデルを JRA-55 にする）で取得して、ほかのモデルと同じ画面で見られます。GSM の予報と同じ時刻の解析値を左右に並べる（2モデル比較）こともできます。
- **公開しない**（ローカル専用・`local_only`）。**自動更新の対象外**（`auto=False`）。キャッシュと画像は自動では消えません。
- **認証は不要**でした（2026-11-10 に確認。tenkizu の README には「認証必要」とあるが、RISH 側の設定が変わった模様）。`jra55.ini` は作らなくてよい。
- **取得の方式**: 配信は NetCDF4 の月ファイル（1変数 200〜630MB）。月ファイルは取らず、HTTP の範囲読み込み（`#mode=bytes`）で**必要な時刻・気圧面（975/925/850/700/500/300/200/100hPa）だけ**を読み、時刻ごとの小さなキャッシュ `data/jra55/<開始時刻>/YYYYMMDDHH.npz`（約3.7MB）に保存します（`jra55_source.py`）。1日分（4コマ）で約15MB＋画像約14MB・約2〜3分、**3日分（12コマ）でも約2分**（同じ5日ブロックの時刻はまとめて読むと追加コストがほぼ無い）。
- **作れる図**: 地域は**アジア域と日本域のみ**（沖縄域・GSM専用の高解像度域は作らない）。図種は 100〜300hPa ジェット、300hPa 湿数、500高度、500/700/850/925/975、850EPT、地上（気圧・風のみ）。**作れない図**: 雲量が無いので「地上（天気）」。降水が無いので地上図は気圧と風だけ（図種名は「降水」のまま）。
- **時間の推移を動かせる（系列）**: 指定した時刻から **N 日分（1/2/3/5/7/10日・6時間毎）を1つの系列**として取得します。画面では、プルダウンの見出しが「**開始**」になり、項目は「5/3(月) 00時UTC から4コマ（＋18h）」の形で出ます（**時刻の選択肢は開始時刻の1つだけ**）。**ほかの時刻（6時間毎）は、予報時間のスライダーと再生で動かします**（FT=0,6,12,…＝開始からの経過時間）。表示は「解析 開始 … ＋30h／解析時刻 …」。予報モデルと同じ形なので、2モデル比較は**解析時刻（開始＋経過）を合わせて**並べられます。画像のキャプションは `JRA-55 ANAL:1959/09/10 12:00(UTC)` と解析時刻を年つきで出す。
- コマンド: `python past_jra55.py fetch 1959092612 [--days 1|2|3|5|7|10]` / `list` / `delete 1959092612 [--png]`。`python make_charts.py jra55 1959092612 --days 3` でも作れる。旧形式（時刻ごとにバラバラ）のキャッシュは、自動で系列フォルダへ移す。
- 地表気圧(PRES)で、地面より下の等圧面をマスクする（JRA-55は地面下を外挿値で埋めているため）。
- 手元の月ファイル（tenkizu の `data/Jra55` と同じ構成）があれば、環境変数 `JRA55_RAW_DIR` で優先して読める（読み取りのみ。削除しない）。

| `com.masahiro.nwp_chart_web_sync` | 公開側で作られた画像を手元へ取り込む（`sync_public.py`） | 30分おき |

| `com.masahiro.nwp_chart_web_token_notify` | cron-job.org 用トークンの期限をSlack DMで通知（2027-02-08 の14日前から。`CRON_JOB_ORG.md`） | 毎日9:05 |

### GSM の自動取得（00/12UTC のみ・ローカル）
GSM は **00UTC と 12UTC の初期値だけ**を、launchd で自動取得・作図します（06/18UTC は手動）。ECMWF・GFS・AIFS は公開サイト側（GitHub Actions）が更新するので、この自動取得の対象は GSM だけです。

- 設定: [launchd/com.masahiro.nwp_chart_web_gsm.plist](launchd/com.masahiro.nwp_chart_web_gsm.plist)（`~/Library/LaunchAgents/` に置いて登録）。1時間おきに確認し、揃っていれば取得・作図、作成済みなら数秒で終わります。
- 実行内容: `update_latest.py --models gsm --init-hours 0 12 --keep-days 3 --jobs 4 --dl-jobs 6`
- **所要時間（実測）**: 初期値1つで約14分（13分42秒）。取得 約590MB（FT72h まで）、PNG 851枚（約130MB）。1日2回で約27分。
- **保管**: 初期値が **3日より古い PNG と GRIB2 を自動で削除**します（`--keep-days 3`）。3日分（約6初期値）で約4.3GB。削除対象は `--dry-run` を付けると確認できます。
- ログ: `logs/gsm_auto.log`
- 手動で 06/18UTC を取る: `python make_charts.py gsm 2026110406`（YYYYMMDDHH、UTC）。
- 登録・停止:
  ```bash
  cp launchd/com.masahiro.nwp_chart_web_gsm.plist ~/Library/LaunchAgents/
  launchctl load ~/Library/LaunchAgents/com.masahiro.nwp_chart_web_gsm.plist     # 登録（自動取得を開始）
  launchctl unload ~/Library/LaunchAgents/com.masahiro.nwp_chart_web_gsm.plist   # 停止
  ```

### 2回目以降（作成済みの画像を見るだけ）
手順の 2) と 3) だけです。**表示するだけならダウンロードは発生しません**（作成済みの画像を読むだけ。オフラインでも見られます）。

### 最新データに更新する
- 画面ヘッダーの **「最新を取得」** ボタン（サーバーが全モデルを並行して更新し、完了すると自動で切り替わります）。
- またはコマンド: `python update_latest.py`（作成済みの初期値は飛ばし、新しい初期値だけ作ります。`--dry-run` で何をするか確認できます）。

### 各モデルの自動取得の初期値と、取得（公開）時刻の目安
**どの初期値を自動で取るか**（公開サイトは cron-job.org が `update-model` を起動して自動更新。ローカルの GSM は launchd）:

| モデル | 自動取得する初期値（UTC） | 取る仕組み | 補足 |
|---|---|---|---|
| **ECMWF** | **00 / 12 / 18**（1日3回） | 公開サイト（GitHub Actions） | 配信は 00/06/12/18 の4回だが、**06Z は取らない**。**18Z も取る**のが GFS・AIFS との違い。00/12Z は144時間先まで配信されるが72時間までを作り、**18Z は90時間先までしか配信されない**（72時間までは作れる） |
| **GFS** | **00 / 12**（1日2回） | 同上 | 06/18Z は取らない（公開容量1GBの都合） |
| **AIFS** | **00 / 12**（1日2回） | 同上 | 配信は6時間刻みで4回/日だが、公開は 00/12Z のみ（容量の都合） |
| GSM（ローカル専用） | 00 / 12 | Mac の launchd（1時間おき） | 06/18Z は手動（`--init-hours 0 6 12 18`）。過去分は「過去分取得」ボタン |
| JRA-55（ローカル専用） | 自動取得なし | 画面の「過去分取得」 | 再解析なので「最新」は無い |

公開サイトは、**ECMWF 00/12/18Z・GFS 00/12Z・AIFS 00/12Z の約2日分**（ECMWF 5・GFS 4・AIFS 4 初期値）を載せます（設定は `nwp_data.MODELS` の `publish_hours` / `publish_keep`）。

**初期値から72時間分が揃う（＝作図できる）までの目安**（`check_availability.py` の実測。2026-11-05〜11-11。標本が少なく、遅れる回もある）:

| モデル・初期値 | 揃うまでの時間 | 揃う時刻（UTC） | 揃う時刻（JST） |
|---|---|---|---|
| GFS 00Z | 約4〜6時間 | 4:00〜6:15 | 13:00〜15:15 |
| GFS 12Z | 約4〜6時間 | 16:15〜18:00 | 翌 1:15〜3:00 |
| AIFS 00Z | 約5.3〜6.8時間 | 5:20〜6:50 | 14:20〜15:50 |
| AIFS 12Z | 約5.5〜9時間 | 17:30〜21:00 | 翌 2:30〜6:00 |
| ECMWF 00Z | 約7.4〜10.4時間 | 7:20〜10:20 | 16:20〜19:20 |
| ECMWF 12Z | 約7.6〜11.4時間 | 19:40〜23:25 | 翌 4:40〜8:25 |
| ECMWF 18Z | 約6.6〜9.6時間 | 翌 0:30〜3:35 | 翌 9:30〜12:35 |
| GSM 00Z / 12Z（ローカル） | 約7〜10時間 | — | 作図完了の実績は 00Z が 15:50、12Z が翌 6:30 ごろ（Mac の稼働と RISH の配信に依存） |

**公開サイトに出るまで**: 揃ってから、次の cron-job.org の起動（UTC 1/4/6/7/9/10/17/18/20/22/23 時の :30 と :55）で作図が始まり、作図は ECMWF が約10分・GFS/AIFS が約1〜9分、公開ブランチへの反映のあと、Pages の配信にさらに約3〜4分かかります。**揃ってから見えるまで、通常30分〜1時間強**です（次の起動までの間隔しだい）。ECMWF の 00Z が 10:21 UTC に揃った回などは、次の起動を待つ分だけ遅れます。

**画面にも載せている**: 通常版はフッターの折りたたみ「各モデルの更新（自動取得する初期値と、揃う時刻の目安）」、画用紙版は「使い方」パネル（H キー）の下の「更新」の節（`web/index.html`・`web/board/index.html`）。値を変えるときは、この表と画面の2か所を直す。

### モデルを比較したいとき

比較のしかたは、上の節 **[モデルを比較する](#モデルを比較する)** を参照してください（通常版の「2モデル比較」と、画用紙版の「図を選んで『モデル違い』」の2通りがあります）。

### バックグラウンドで起動・停止する場合
```bash
nohup /opt/anaconda3/envs/met_env_310/bin/python server.py > /tmp/nwp_server.log 2>&1 &   # 起動
kill $(lsof -ti :8790)                                                                      # 停止
```

### うまくいかないとき
| 症状 | 対処 |
|---|---|
| `ModuleNotFoundError`（pygrib など） | `python3` ではなく `/opt/anaconda3/envs/met_env_310/bin/python` を使う |
| `Address already in use`（ポートが使用中） | `python server.py --port 8791` のように別のポートにする（URLのポートも変える） |
| 「manifest.json を読めません」「天気図がまだありません」 | 手順 1) の `update_latest.py` を先に実行する |
| モデル選択に GSM が出ない | GSM を作っていない。`make_charts.py gsm ...` か `update_latest.py` で作る |
| 比較したいモデルが「画像なし」 | 予報有効時刻が重ならない（相手の初期値より前の時刻など）。↑キーで時刻を進める |
| 画像が古い・初期値が増えない | 「最新を取得」を押す。配信元に新しい初期値がまだ無い場合は作られない |

- サーバーは `127.0.0.1`（自分のPCだけ）で待ち受けます。**他の端末・インターネットには公開されません。** 「最新を取得」ボタンもローカルからだけ使えます。
- 旧版 [gsm_chart_web](https://github.com/masauehr/gsm_chart_web)（GSM のみ、ポート 8780）とは**ポートが違うので同時に起動できます**。
- 公開サイト（GitHub Pages）にはローカルのデータは影響しません。公開側は GitHub Actions が別に更新します（下記）。

- 通常版は **「2モデル比較」**、画用紙版は **「図を選んで『モデル違い』」** でモデルを比較できます（[モデルを比較する](#モデルを比較する)）。

公開は **gh-pages ブランチ**方式（詳細は [PUBLISH.md](PUBLISH.md)）。
- **画面だけの修正**は、push すると `deploy-web.yml` が**画像を作らず**画面ファイルだけを数十秒で反映する。
- **データの更新**は `update-model.yml` が 1日11回（UTC 1:30 / 4:30 / 6:30 / 7:30 / 9:30 / 10:30 / 17:30 / 18:30 / 20:30 / 22:30 / 23:30。配信実測に合わせた時刻）、**モデルごとに別ジョブで並行**して作図し、できたモデルから公開する（取得完了を待たずステップごとに作図）。GitHub の `schedule` は遅れるため、同じ時（UTC）の :30 と :55 に **cron-job.org から `workflow_dispatch` でも起動**する（1日16回）（2026-11-10〜。設定・トークン期限は [CRON_JOB_ORG.md](CRON_JOB_ORG.md)）。
- 公開物は PNG と manifest だけで、元データ（GRIB2）は公開サーバーにも保存されない。約2日分を載せる（ECMWF は 00/12/18UTC の5初期値、GFS・AIFS は 00/12UTC の4初期値。合計約1.0GB）。

出典・ライセンス・免責・改変の表示は画面に常時出している。

### 容量の制約（GitHub Pages 1GB）
- 公開サイトは **1GB まで（サイト＝リポジトリ単位）**。現状 **約0.88GB**（ECMWF 5・GFS 4・AIFS 4 初期値）で、余裕は約0.1GB。確認: `gh api repos/masauehr/nwp_chart_web --jq .size`（KB）。
- **方針（2026-11-10）: 現状で様子見**。図種・地域・公開個数を増やすときは、先に容量を見積もる。足りなくなったら、①個数・図種を絞る ②リポジトリをモデルごとに分ける。WebP は実測で効果が小さい（可逆 約-10%、非可逆は線画のため増える）ので見送り。詳しくは [PUBLISH.md](PUBLISH.md) の「容量の制約と対応方針」。

### 定期起動に使っている cron-job.org（概要）
- **cron-job.org** は、「決めた時刻になったら指定のURLにアクセスしてくれる」**無料の外部cronサービス**。ここでは、各時の :30 と :55（UTC・1日22回。cron-job.org の画面は JST で設定している）に、**GitHub の API で `update-model` を起動する合図**を送らせている。
- 使う理由: GitHub Actions 自身の定期実行（`schedule`）は時刻が保証されず、数時間遅れたり間引かれたりする（2026-11-09 に約10時間停止）。Mac にも頼りたくないので、**時刻の正確さは cron-job.org、処理は GitHub Actions** と役割を分けた。`schedule`（1日11回）は予備。
- 仕組み: cron-job.org → `POST .../actions/workflows/update-model.yml/dispatches`（`workflow_dispatch`・専用トークン認証）→ `update-model` が起動 → 揃った初期値だけ作図して公開。揃っていなければ何もしないので、何度呼んでも安全。
- 注意: 専用トークンに**期限**がある（2027-02-08 01:45 UTC。14日前から Slack DM で通知）。詳しい仕組み・設定・更新手順は [CRON_JOB_ORG.md](CRON_JOB_ORG.md)。

**GSM はローカル専用**です。ローカルで `python update_latest.py` や画面の「最新を取得」を使うと、GSM も含めて4モデルを比較できます（公開サイトには GSM を載せません。詳細は [nwp-chart-web.md](nwp-chart-web.md)）。

**モデル比較**: 通常版の「2モデル比較」（左右に並べる）と、画用紙版の「モデル違い」（図を選んで他のモデルを追加）の2通りで、ECMWF（IFS）・AIFS・GFS を比べられます（IFS と AI モデルの差が見どころ）。使い方は上の「[モデルを比較する](#モデルを比較する)」を参照。最新の初期値がモデルで違っても、**予報有効時刻を合わせて**表示する（見出しに `GFS [11/04 00Z +6h]` のように初期値と予報時間が出る）。

## 図種・地域

- 図種（**高層→地上の順**に並ぶ。2026-11-10〜。並びは `nwp_charts.CHARTS` の定義順。画面（`web/app.js` の `CHART_ORDER`）にも同じ順を持つ。図種を足すときは両方に入れる）: **100hPa ジェット（GSM・JRA-55のみ・アジア域・tenkizu の GSM_100hPa.py と同じ表示）** / **200hPa ジェット（アジア域のみ）** / 300hPa ジェット / **300hPa 気温・湿数（アジア域のみ）** / 500hPa 高度・渦度 / 500hPa 気温・湿数 / 700hPa / 850hPa EPT・SSI / 850hPa 気温・湿数 / 925hPa / 975hPa（GFSのみ）/ 地上（天気・SSI）/ 地上（降水）

- 地域: 日本周辺 / 沖縄周辺 / 東アジア広域
